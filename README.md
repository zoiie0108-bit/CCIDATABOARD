# 文化产业观察站 · 第一期

政策名录 + 影视文化产业监测。**输出为单个 HTML 文件**，数据内嵌，可离线打开，也可放到任意静态托管供手机、平板、电脑跨端查看。

## 三种使用方式

| 场景 | 做法 |
|---|---|
| 本机查看 | 双击 `dist/index.html` |
| 手机 / 平板查看（同一 Wi-Fi） | 双击 `start.bat`，按窗口提示打开 `http://<电脑IP>:8787` |
| 远程 / 分享 | 把 `dist/index.html` 上传到任意静态托管（对象存储、GitHub Pages、Nginx） |

## 更新数据

```bash
node server/build.js          # 抓取官方栏目 + 采集文博周报 + 重新构建
node server/build.js --no-sync  # 只用现有数据重新构建（不联网）
node server/build.js --no-heritage  # 抓政策但跳过文博采集
```

或双击 `update.bat`（抓取并构建）。构建完成后刷新页面即可看到新数据。

文博周报也可以单独跑：

```bash
npm run collect:heritage                              # 默认回溯 4 年列表
npm run collect:heritage -- --pages 20 --weekly 8     # 只翻 20 页、保留最近 8 期
```

采集是**增量归档**：`data/heritage.json` 里已有的期次会保留，新抓到的覆盖同期。

## 页面

| 页面 | 说明 |
|---|---|
| 概览 | 三组大盘卡片，顺序为文化产业背景（国家统计局）→ 文旅/体验 → 电影/院线，共 11 张，每张带数据期与发布日期；重点政策动态 |
| 政策库 | 名录表格，标题直接跳官方原文；支持关键词、地区、主题、类型筛选与 CSV 导出 |
| 产业监测 | 顶部「重点数据提示」卡片 → 1.1 文化产业背景 → 1.2 文旅/体验 → 1.3 文博周报（周报要点 / 客流 / 年度底数 / 展讯）→ 1.4 电影/院线 → 来源优先级 → 数据缺口 |

**本期不设二级页面**：点击政策标题直接打开官方原文，不在站内渲染详情。也**不设人工核验流程**——数据由本地抓取后静态发布，任何修改都需要重新构建。

## 数据约定

- 政策名录取自官方栏目，标题与链接指向原文；摘要为自动抽取，仅供参考。
- 采集时间与发布日期独立存储；发布日期缺失不进入名录。
- 指标分三组，页面显示顺序统一为：文化产业背景（国家统计局）→ 文旅/体验 → 电影/院线，区域对照单列。
- 指标区分 `官方` / `测算值` / `非官方` 三档，测算值必须写公式。
- 日均、人均等派生指标与总量指标分开展示，假期天数差异写入口径说明。
- 缺失指标显示「—」并列入数据缺口，不插补、不推算。

## 指标模型

每个指标都带「数据期 + 发布日期 + 预计下次发布」，支持混合频率（档期 / 月度 / 季度 / 年度）：

| 字段 | 说明 |
|---|---|
| `group` | `film` / `tourism` / `macro` / `region` |
| `frequency` | `holiday` / `monthly` / `quarterly` / `annual` |
| `period` | 当前值对应的数据期，如 `2026 国庆档` |
| `value` / `valueLabel` | 数值；区间类用 `valueLabel`（如 `20%–25%`） |
| `yoy` / `comparison` | 同比百分比；可读的对比说明 |
| `publishedAt` | 官方发布日期，缺失为 `null` |
| `nextRelease` | 预计下次发布日期，仅填写有明确节奏的指标 |
| `history` | 历史序列 `[{period, value, yoy, publishedAt}]`，≥3 期且 `trendBasis ≠ none` 才绘制趋势线 |
| `trendBasis` | `value` 连绝对值 / `yoy` 连同比增速 / `none` 不连线 |
| `caliber` / `formula` | 口径说明与计算方式 |
| `sourceName` / `sourceLevel` | 来源与等级：`官方` / `测算` / `非官方` |
| `dataStatus` | `reported` / `verified` / `missing` |

页面会按 `publishedAt` 计算新鲜度：≤30 天「数据较新」，31–60 天「可用」，>60 天「待更新」。

## 指标数据采集（M2 半自动）

官方数据多为 PDF 或带表格的网页，直接正则抽取容易把数字和单位对错，因此采用「机器找候选 + 人工确认」：

```bash
node server/collect-indicators.js   # 抓官方新闻，产出 data/indicator-candidates.csv
# 用 Excel 打开 CSV，把要采纳的行 accept 改成 Y，保存
node server/promote.js              # 合并进 data/indicators.json
node server/build.js --no-sync      # 重新生成页面
```

候选 CSV 每行包含：指标代码、期间、数值、单位、同比、发布日期、来源、原文链接、原文句子。原文句子用于人工核对，避免只看数字下判断。

采集范围（`server/collect-indicators.js` 中的 `INDICATOR_SOURCES`）：

| 来源 | 抓到什么 | 备注 |
|---|---|---|
| 国家电影局 · 工作动态 / 行业资讯 | 档期票房、观影人次、银幕数 | 每篇只讲一个期间，用于判断档期数据 |
| 文化和旅游部 · 要闻信息 | 各假期出游人次、出游总花费、大型演出场次 | 已翻 8 页，覆盖春节至国庆多个假期 |
| 国家统计局 · 最新发布 | 文化及相关产业营业收入、内容创作生产、文化新业态 | 已翻 36 页，完整覆盖累计季度序列 |

新增来源只需在 `INDICATOR_SOURCES` 登记；`listUrls` 支持多页，`titleRe` 可按来源收窄标题命中范围。

抽取规则（避免把数字和单位对错）：

- 按指标锚点词就近取值（票房 / 观影人次 / 银幕 / 出游 / 营业收入…），并强制单位与指标匹配；
- 句中出现「截至 / 累计 / 全年 / 总票房」等累计口径时丢弃，避免把累计值当成档期值；
- 一篇文章只对应一个期间；句中期间与标题期间不一致，视为同比对照句并跳过。

## 分地区票房（为什么一半靠人工）

地方票房没有稳定的官方数据栏目：上海市电影局、北京市政府搜索、杭州/浙江省文旅厅等站点要么是 JS 渲染，要么根本没有「票房」栏目。当前做法是两条腿走路：

**自动扫描**（`INDICATOR_SOURCES` 中以 `region-` 开头的 4 个来源）

| 来源 | 栏目 |
|---|---|
| 北京市政府 · 政务动态 | `beijing.gov.cn/ywdt/gzdt/` |
| 上海市文化和旅游局 · 文旅要闻 | `whlyj.sh.gov.cn/wlyw/` |
| 杭州市文化广电旅游局 · 门户文章 | `wgly.hangzhou.gov.cn` |
| 浙江省文化广电和旅游厅 · 首页文章 | `ct.zj.gov.cn` |

只要这些栏目出现「浙江 / 杭州 / 北京 / 上海 … 票房 … 亿元」的句子，就会产出候选进 CSV，走同一条人工确认流程。目前这些栏目没有票房类文章，所以候选数长期为 0 —— 这是事实，不是脚本坏了。

**人工补录**（`data/region-manual.csv`）

```csv
indicatorCode,indicatorName,period,value,unit,yoy,publishedAt,sourceName,sourceUrl,note
ZJ_BOX_OFFICE,浙江省电影票房,2026 年度,48.6,亿元,5.2,2027-01-20,浙江省电影局,https://…/xxx.html,省局年度通报
```

```bash
npm run import:regional     # 写入 data/indicators.json
npm run build:only          # 重新生成页面
```

约束：`sourceUrl` 必填，没有来源链接的行会被跳过并打印提示；允许的代码只有 `ZJ_BOX_OFFICE` / `HZ_BOX_OFFICE` / `BJ_BOX_OFFICE` / `SH_BOX_OFFICE`。缺数据时页面显示「未获取」，不放估算值。

## 文博周报（国家文物局）

产业监测的 1.3 组，数据来自两个官方渠道，与指标库分开存放（`data/heritage.json`），因为它的频率和结构都与指标不同。

### 采集内容

| 内容 | 来源 | 频率 | 形态 |
|---|---|---|---|
| 周报要点 | 国家文物局「一周文物动态摘编」 | 每周 1 期 | 条目流：地区标签 + 标题 + 首段摘要 |
| 展讯名录 | 国家文物局「看展览｜博物馆展讯速览」 | 每月 1 期 | 表格：博物馆 / 展览 / 地点 / 时间 / 简介 |
| 博物馆客流 | 国家文物局新闻稿（假期、暑期口径） | 每年数个假期 | 期间 + 接待观众 + 同比 + 日均同比 |
| 年度底数 | 文旅部《文化和旅游发展统计公报》 | 年度 | 备案博物馆数、接待观众、同比、陈列展览 |

### 抓取实现要点

国家文物局网站有三个容易踩的坑，`server/collect-heritage.js` 已处理：

1. **只有 http 通，https 直接失败**，URL 必须写 `http://www.ncha.gov.cn/...`；
2. **列表不是普通 HTML**：`<datastore>` 里塞 CDATA 包裹的表格行，链接用单引号 `href='...'`，常规双引号正则取不到；
3. **分页走独立接口**：`dataproxy.jsp?columnid=722&page=N`，一次返回约 300 条，可稳定翻页。

采集分两阶段以控制成本：先只翻列表（便宜）挑出三类候选，再只对需要的条目抓详情——周报取最近 12 期、展讯取最近 6 期、客流全部抓。

### 口径与边界

- 客流数据各假期天数不同（2025 春节 7 天、2023 国庆 8 天），总量不可直接比较，页面因此单独列出「日均同比」列，只在官方给出日均口径时才可跨年对照。
- 年度底数里「—」表示该年度公报未公布该项（例如 2024 年公报未发布备案博物馆数），不做补算。
- 文创销售额没有官方时序发布，只有活动期的第三方平台披露，因此**不进指标卡**，避免与官方数据并排显示造成误读。
- 周报条目为主管部门自身的工作动态汇编，不是产业统计数据；页面按「观察要点」呈现，不做数量统计。

## 重点数据提示（自动生成）

产业监测页顶部的提示卡片不是手写文案，而是按指标数据实时生成：

1. 取 `yoy` 绝对值 ≥ 5% 且 `dataStatus ≠ missing` 的指标，按变动幅度降序取前 4 项；
2. 每项输出三段：**观察到的事实**（指标 + 涨降幅度 + 数据期 + 来源）、**建议同时关注**（关联指标）、**可能原因**（待逐条验证）；
3. 关联指标与原因来自 `web/template.html` 的 `INSIGHT_META`，按指标代码登记；未登记的新指标会退回到通用提示；
4. 卡片底部固定声明：以上为观察到的变化与建议核查方向，不构成因果结论；同时列出未获取指标数与测算/非官方指标数。

调整阈值改 `INSIGHT_THRESHOLD`；新增指标时在 `INSIGHT_META` 里补 `focus`（该看哪些指标）和 `causes`（可能原因），提示会自动出现。

这条设计的用意是：页面只提出「看什么、为什么可能」，不替用户下「某项政策提升了产业表现」这类结论。

## 趋势线

`history` 至少 3 期才会绘制迷你趋势线，最多取最近 12 期。是否连线由 `trendBasis` 决定：

| `trendBasis` | 含义 | 适用例子 |
|---|---|---|
| `value` | 直接连绝对值 | 银幕总数（期末存量） |
| `yoy` | 连同比增速 | 文化及相关产业营收（累计口径，期间长度不同，绝对值不可比） |
| `none` | 不连线，只列已收录期间 | 各假期出游人次、各档期观影人次（假期天数不同） |

`none` 的指标在产业监测表下方会显示「已收录 N 期（期次列表）；各期口径不同，不做趋势连线」，避免用一条线暗示不存在可比性。

## 已知限制

- 浙江、杭州部分栏目由 JavaScript 动态渲染，服务端只能取到首页可见条目，覆盖偏少；需要继续找可静态访问的栏目或改用人工补录。
- 指标以人工录入为主，尚未接入统计公报自动解析。
- 未实现：定时调度、数据库、权限控制、AI 摘要、趋势图表。
